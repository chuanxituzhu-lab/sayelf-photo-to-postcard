# Build Decision Record: optional local vision

- **Problem:** filenames and pixel heuristics are not enough for arbitrary unfamiliar images.
- **Closest existing solutions:** IBM TensorFlow.js Web App (local browser inference and cache pattern); official TensorFlow.js COCO-SSD and MobileNet packages (maintained browser models); IBM Granite Vision served by local Ollama.
- **Decision:** Integrate and improve rather than build a new vision model. Keep the browser models as the dependency-free baseline and add an optional IBM Granite Vision adapter using the local Ollama API, with a deterministic browser fallback.
- **Measurable improvement:** browser labels can be augmented with IBM scene, subject, lighting, composition and color evidence; the merged evidence refreshes scene deconstruction, all four 03 copy fields, and bilingual prompts from the current upload. The image is resized in the browser and sent only to `127.0.0.1:11434` when IBM is enabled.
- **Current copy-matching rule:** COCO-SSD, MobileNet, pixel statistics, composition and bounded local copy history now drive all four 03 fields; each recognized upload receives a new four-field combination when a prior combination already exists.
- **Fixed master rule:** the confirmed reference is the canonical template: original photo above, metadata/copy and three swatches at lower left, and same-scene artistic translation at lower right. Style changes are limited to the lower-right image slot; subject-family copy cues cover natural landscapes, city bridges, tea terraces, animals, and travel portraits.
- **Whitespace rule:** local reference images contribute a small vocabulary of whitespace rhythms (sketch-air, centered editorial, handwritten-left, quiet portrait, textile collage). The chosen rhythm can change internal margins, typography breathing room and irregular edges inside the lower-right slot, but never changes the source photo, lower-left information block, macro slots or same-scene identity.
- **Workflow distillation:** merge the typographic photo-manipulation workflow and the travel postcard workflow into selectable local templates. The default fused template is a 3:4 vertical, exact 50/50 source-photo and lower type–image poster; the established information master and front/back physical-postcard display remain comparison options.
- **Non-goals:** no cloud vision endpoint, no custom training pipeline, no model weights committed to the repository or forced into the single-file default package, and no redesign of the fixed postcard layout.
- **Safety/data boundary:** user images remain local/sensitive; only public open-source model bundles are downloaded by the installer; user photos and generated previews are not published.
